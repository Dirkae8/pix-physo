# PIXPHYSO

Пиксельная физическая песочница с автономным HTML, графикой WebGL2 и моделями веществ, тепла, воздуха и электричества.

## Готовые файлы

- [PIXPHYSO-Release.zip](./PIXPHYSO-Release.zip) — все варианты запуска.
- [PIXPHYSO.exe](./PIXPHYSO.exe) — Windows x64. Отдельное окно приложения, страница встроена в EXE; браузерное окно не запускается. Нужен установленный Microsoft Edge WebView2 Runtime с поддержкой WebGL2 (обычно уже установлен в Windows 10/11).
- [PIXPHYSO.apk](./PIXPHYSO.apk) — Android 6.0 и новее, локальный WebView, без сетевых разрешений. Требуется поддержка WebGL2 в системном Android WebView. APK подписан самостоятельным ключом; Android может запросить разрешение на установку из этого источника.
- [PIXPHYSO.html](./PIXPHYSO.html) — автономный файл для современного браузера, работает без сервера и интернета.

Подпись APK самоподписанная, а EXE не имеет доверенной цифровой подписи: системные предупреждения при установке или запуске возможны. **В этой версии APK подписан новым постоянным ключом**, так как исходный ключ был утерян: перед установкой удалите предыдущую версию приложения. Нативный запуск на реальных Windows и Android устройствах в этой среде не проверялся.

## Управление

- Выберите материал или инструмент в нижней панели и рисуйте мышью или касанием. Категории находятся справа/снизу.
- Выберите **«Контроллер»** и нажмите на точку поля. Панель показывает текущие данные именно этой клетки и ищет для подписи ближайшее свободное место; стрелка указывает на клетку. Повторное нажатие рядом удаляет контроллер. Очистка поля и смена разрешения удаляют контроллеры.
- Над полем находится **отдельная панель режимов**: Реальный / Тепло / Давление / Ветер / Ток / Нагрузка. Она всегда видна (раньше выбор был спрятан в `select` в левой панели), работает кликом и клавишами `Q` / `E`, на телефоне прокручивается горизонтально. Справа на панели — симуляционные часы и текущая скорость. В поиске появилась кнопка очистки, а в подсказке предмета — его реакции и мод.
- Колёсико меняет размер кисти, правая кнопка стирает, Shift рисует линию, пробел ставит симуляцию на паузу. Горячие клавиши: `F` — один шаг физики, `Ctrl+Z` — отмена, `R` — направление вентилятора/насоса/диода, `N` — показать только новинки, `Q`/`E` — режимы, `0–7` — быстрый выбор категории. Клавиши не перехватываются, пока фокус находится в текстовом поле, списке или открытом окне. На телефоне кнопка «Среда» открывает параметры среды; выбор предметов прокручивается, а в альбомной ориентации расположен справа. Настройки GPU и меню выхода на телефоне скрыты.
- Доступен **222 предмета**: 122 исходных и **100 новых**. У каждого — справочные плотность, теплоёмкость, теплопроводность, температуры фазовых переходов, горючесть и прочность; в подсказке и строке выбранного предмета эти данные видны. Кнопка «+100 новых» (клавиша `N`) оставляет в каталоге только новинки. Часть моделей — **приближённые общие модели фаз**, а не полная индивидуальная химия каждого вещества.
- **Время честное:** при `1×` одна симуляционная секунда равна одной реальной независимо от FPS (фиксированный такт 1/60 с, накопитель по `performance.now()`). Скорости реакций заданы в **1/секунду** и переводятся в вероятность такта, поэтому вода больше не вскипает за секунду, а пламя живёт несколько секунд. `2×`/`4×` увеличивают число тактов, но не ускоряют каждую реакцию по отдельности. При сильной просадке FPS действует жёсткий предел тактов и бюджет подшагов: физика слегка замедляется, но **никогда не устраивает спираль смерти** (медленный кадр → больше тактов → ещё медленнее).
- **Исправлены пар и огонь:** у водяного пара появилась конденсация и рассеивание — раньше он был «бессмертным» и скапливался густым облаком даже над водой 30 °C; испарение при низкой температуре сведено к минимуму. Огонь подпитывается от соседнего топлива, фитиль с впитанным маслом держит устойчивое пламя, а шейдер рисует яркое ядро и языки вместо тусклого квадрата.
- Среди новых предметов: фитиль, пластик ABS, ПВХ, полиэтилен, кевлар, бумага, картон, пенопласт, куриный бульон, «сухая вода», растительное и оливковое масло, молоко, уксус, 10 новых взрывчатых веществ, пьезоэлемент, термопара, магнит, пылесос, молот и сушилка. Фитиль капиллярами тянет масло и керосин, «сухая вода» отдаёт воду при нагреве, сода с уксусом выделяет CO₂, а пьезоэлемент вырабатывает напряжение от нагрузки.

- «Выделить схему» позволяет сохранить прямоугольный фрагмент через меню «Миры» и вставлять его повторно. Там же находятся локальные слоты мира и краткая справка; данные сохраняются во внутреннем хранилище приложения.
- При размещении вентилятора, диода и других направленных устройств задайте направление стрелками. Вентилятор и насос требуют питания; двумя пальцами можно масштабировать и перемещать вид.

Полный перечень готовых механизмов и незавершённых функций — в [UPDATE-NOTES.md](./UPDATE-NOTES.md).

## Архитектура: один файл на каждый элемент

- `src/materials/elements/` — **251 отдельный `.ts`-файл**: по одному на каждое вещество, включая скрытые продукты реакций. В файле лежат полные характеристики (`def`), список реакций (`reactions` со скоростями в 1/с), табличное поведение и, если нужно, исполняемые хуки `onStep` / `onVoltage` / `onBrush`.
- `src/materials/elementApi.ts` — публичный контракт элемента и `chancePerTick()`. `src/materials/elementRegistry.ts` превращает модули в плоские LUT, которыми пользуются решатели: в движке нет `if (m === БУМАГА)`, поведение приходит из файла элемента.
- `src/mods/` — **отдельный файл-манифест на каждый мод** (`core.materials`, `phase.reactions`, `expansion.solids`, `expansion.powders`, `expansion.fluids`, `expansion.energy`) плюс `installMod()` / `installElement()` для сторонних модов. `src/materials/ids.ts` задаёт лимит `MAX_MAT_ID = 256` и первый свободный id `251`.
- `node scripts/generate-elements.mjs` (`npm run elements:generate`) пересобирает файлы элементов и манифесты из текущего каталога. `registry.ts` и `expansion.ts` после генерации не перезаписываются — это движковые таблицы и константы.
- **Аудит каждого элемента** выполняется генератором: состояние и категория сверяются (в «Твёрдых» только `solid`, в «Сыпучих» только `powder`), у листовых материалов исправлена унаследованная от опилок «сыпучесть» — бумага, картон, фитиль, ткань, кевлар теперь честно твёрдые тонкие листы со своей фактурой. Отдельно выверены вязкость/дисперсия у 35 веществ, прочность, пористость и продукты горения.

### Текстуры и огонь

Переписан рендер миниатюр твёрдых: симметричная изометрия вместо «съехавшей» левой грани, все узоры считаются в координатах грани `(u,v)`, для листов добавлен отдельный рендер сложенного листа. В WebGL2-шейдере у волокон, резины, воска, керамики, ВВ и инструментов появились собственные ветки вместо плоской заливки; пламя рисуется субпиксельным языком с мягкими краями, а не однотонным квадратом.

## Архитектура и ограничения

Теплопроводность ограничена для устойчивости; спирт образует собственный пар без взрывов от каждой клетки. Тонкие стены закрывают ячейки воздуха, ветер вводится через открытые границы, а вентиляторы воздействуют на огонь и дым. Сетка воздуха имеет шаг 4×4 пикселя, поэтому узкие проходы могут перекрываться приближённо.

Исправления физики этой версии: сообщающиеся сосуды больше не блокируются глобальным перепадом давления, перенос жидкости не залипает на одной клетке-доноре, буферы поверхностей масштабируются под мир 960×540, жидкость растекается на несколько клеток за такт и корректно обменивается с более лёгкой жидкостью; вода при атмосферном давлении кипит с учётом скрытой теплоты, а в режиме «Баланс» фазовые переходы выполняются один раз за такт, а не дважды. Водные жидкости гасят огонь, а масла — нет.

Оптимизация без потери качества: **активные области** — один проход `World.refreshActivity()` за такт считает активные строки, горизонтальные границы вещества, флаги «есть газы / жидкости / цепи / нагрев»; химия, термодинамика, механика, электрика и устройства пропускают пустые строки И пустые столбцы. **Воздух переписан**: спокойные кадры не считают релаксацию, вентиляторы впрыскиваются только по найденным ячейкам, буферы давления/скорости меняются местами вместо копирования массивов, маска стен не строится для блоков вне вещества. BFS сообщающихся сосудов кеширует координаты вместо деления на каждом шаге. Плюс метки поколений, плоские LUT, безаллокационные обходы цепей, `sqrt` вместо `hypot`, инкрементальный счётчик частиц, пропуск электрики/волн/механизмов когда их нет. По умолчанию 2 подшага вместо 3 (ползунок в настройках до 6); разрешение и HDR/PBR не менялись. Замер на стартовой сцене 480×270: кадр ~13 мс вместо ~16 мс, а при просадке до 20 FPS — ~20 мс вместо ~46 мс (регресс со спиралью смерти устранён). Сборка релиза больше не требует системной утилиты `zip`.

Каталог материалов рассчитан на 256 ячеек (`MAX_MAT_ID`): `0..144` — исходные вещества, `145..244` — 100 новых предметов, `245..250` — скрытые продукты реакций. Поле мира хранит id в `Uint8Array`, поэтому **255 — жёсткий предел** для любого будущего вещества. Старые сохранения совместимы; при загрузке проверяется, что id вещества существует в текущей таблице.

Физические решатели выполняются на **CPU**, а визуализация и эффекты — на **GPU через WebGL2**. Режим «Баланс» увеличивает количество CPU-итераций; доли нагрузки 90/10 и 70/30 не реализованы и не измеряются. Модели физики являются приближениями, а не научным симулятором.

## Разработка и сборка

```bash
npm ci
npm test                 # 82 теста, один воркер — стабильно в песочницах с ограниченным TEMP
npm run build            # tsc (с запасом памяти) + vite
npm run dev
npm run build:release    # PIXPHYSO.html + PIXPHYSO-Release.zip, без внешнего zip
npm run elements:generate # пересобрать 251 файл элементов и манифесты модов
```

Для нативных пакетов сначала соберите HTML, затем выполните `scripts/build-windows.sh` (нужен Python с `ziglang`, `ZIG_PYTHON`, а также `WEBVIEW2_INCLUDE` с заголовком `WebView2.h` из Microsoft WebView2 SDK; для примера он также имеется в npm-пакете `webview-node@0.1.5` в `bin/source/include`) и `scripts/build-android.sh` (JRE/keytool, apktool и apksigner, переменные указаны в скрипте). Текущий приватный ключ хранится вне репозитория (`~/.android/pixphyso-release.keystore`), пароль в документацию не включается. Для обновления приложения нужен тот же ключ; потеря ключа требует удаления старой версии перед установкой. После сборки оба пакета можно добавить в архив общим скриптом `scripts/build-native-release.sh`.

Тесты: `npm test` проверяет тепло и горение, запертые воздушные потоки и вентиляцию через отверстия, отклонение огня вентилятором, гидростатику, электроцепи, каталог из 222 предметов, целостность 251 файла элементов и 6 модов, реальное время `1×`/`4×`, отсутствие спирали смерти, конденсацию пара при 30 °C, пламя на фитиле и активные области. На Windows и Android фактический запуск пакетов требует проверки на устройстве.
